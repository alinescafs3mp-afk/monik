# Финальный бэклог: обязательное отдельно от пожеланий

## P0: до объявления готового установленного продукта

| Задача | Критерий завершения |
|---|---|
| Штатная CLI-команда `monik tui` | Help и опции зарегистрированы; установленный wheel запускается вне исходного каталога; --once, HTTP/PTY, resize/выход/termios проверены; один серверный Collector |
| Ложный конфликт reset int/float | Старый канонический снимок и численно равный повтор не конфликтуют; provenance сохраняется; bool и реальные изменения не приравниваются; без смены UID/схемы |
| Каталог профилей в вебе | После all→Sol→refresh доступен Astra; unknown не превращается в all; сохранены фильтр API, login/logout и история |
| Own-config/token/lock и установщик | Проверены symlink/hardlink/0600, атомарная запись с уникальным tmp, не меняются источники; активный user/system unit не дублируется; rollback работает |
| Реальный веб-транспорт | Вход, SSE, два браузера/вкладки, потеря связи, сон/возврат, 401 и no stale private DOM; без ослабления TLS/CSP или обхода browser policies |
| Landlock и O13 на хосте | Production serve проходит штатно без root; монитор не пишет в источники и не удерживает/переподключает TUI; не меняются модели/ultra/параллелизм; атрибуция по PID, а не diff активного rollout |
| Финальный main + развёртывание | Полный тестовый прогон, обычный push, origin/main=HEAD, один постоянный сервис, рабочий URL и краткая русская памятка |

Подкоманда, int/float и UI-каталог остаются задачами Сола, не включены молча в текущую передачу. Для смены сетевой конфигурации не угадывать адрес. Реальные дефекты аутентификации/целостности закрывать до публичного доступа.

## P1: доводка графика без разрастания архитектуры

- Настоящий HTTP/SSE в Chromium/Firefox и на Android, 360/390/412/768/1440 px, портрет/ландшафт, клавиатура/сенсор, обе темы, focus и экранный диктор. Component bridge не заменяет эти испытания.
- Нагрузочный прогон на копии реальной БД: выбранный 24-часовой диапазон, непрерывный backfill, несколько клиентов, частые commits, disk pressure. Проверить query budget, CPU/RAM и размер ответа. Порог SLA согласовать по фактическим измерениям, не произвольным цифрам.
- Ограниченный timeout fetch, отказ/отмена старого запроса при быстрой смене периода, отработка API 503 и login-refresh после истечения сессии. Сохранить текущие abort/generation guards.
- При сдвиге окна удерживать инспектор по времени, если пользователь изучает точку; не переключать его незаметно по тому же индексу. Разделить follow-live и ручное чтение.
- Явная подпись при скрытии всех рядов, разные штрихи/цвета для большого числа профилей, легенда с full technical ID при необходимости. Не заменять отсутствие измерения нулём.
- Тесты UTC/DST, перевод часов, границы секунды/корзины, будущее/неточное время источника. Исторический `at` API имеет горизонт знания; сохранить это отличие от реконструированной ленты.

## P2: желательные функции

1. Клик по пику → лента ответов этого профиля/корзины, с тем же временем знания и точными half-open bounds; ссылки на provenance. Не «приписывать» токены одной tool-команде без evidence.
2. Исторический picker T и кнопка LIVE; сохранение hours/metric/visible profiles в URL без токена. Возможность сравнить два периода при понятной семантике.
3. Отдельные ряды root и children, детализация по session/model. Не суммировать родительский cumulative с детьми и не переносить позднюю parent-связь в прошлое без доказательства.
4. Простой CSV/JSON экспорт только измерений текущего окна с предупреждением о приватности. Все числовые данные, не тексты/ключи пользователя.
5. Отметки известных разрывов источника/периодов backfill и окно свежести. «Нет записей» пока не отличает простой от отсутствия сбора; для отличия нужна история покрытия, не эвристика.
6. Небольшой cache/incremental projection лишь после нагрузочного подтверждения необходимости. Cache key включает bounds, profiles, cursor/конфликты; не создавать отдельный сервис аналитики.

## P3: прежний расширенный контракт

Thread-history backfill, содержимое handoff-файлов, полный chunked просмотр outputs сверх ingestion truncation, retention/архивация с сохранением provenance и восстановления. Эти функции не реализованы полностью; read-only app-server или provider API не добавлять как скрытую замену.

«Все возможности видны в едином чате Friday», model_changer, оптимизация расходов моделей, lifecycle management и диспетчер не относятся к monik. Не снижать reasoning или число агентов под видом оптимизации монитора.

## Известные точечные проверки

В старом app отсутствующий cursor может дать 500 вместо клиентского 400: обработать узко, не ловить все исключения и не скрывать bugs. В `series` UI исходный timestamp отсутствует у части usage: их количество видно отдельно, backfill остаётся неполным. Временные state-копии после аварии требуют аккуратной очистки только собственного каталога. Старые JSON-протоколы в docs/evidence являются историческими, не текущей зелёной приёмкой.
