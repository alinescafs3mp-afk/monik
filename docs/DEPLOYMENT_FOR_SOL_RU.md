# Развёртывание: выполнить CLI-Солу на машине владельца

Владелец поручил полную установку завершённого monik. В этой передаче на его хосте ничего не запускалось. Не выдавать команды из примера за уже выполненную установку.

## 1. Проверить рабочее место и изменения

Установку выполняет обычный владелец сессий, не root. Отдельный постоянный checkout и venv monik, не окружение Пятницы. До изменений выясни `pwd`, `id`, `git status --short`, `git remote -v`, Python/SQLite, ядро и состояние обеих возможных служб:

```bash
systemctl --user status monik.service --no-pager
systemctl status monik.service --no-pager
ip -br -4 address
ss -ltn
```

Неуспех status для отсутствующей службы нормален, это не причина создавать вторую наугад. Не запускать массовые discovery/network/model probes. Приватное обследование описывает прошлый снимок, текущие пути и адреса проверяются заново.

Если архив без .git: создай соседний clone `https://github.com/alinescafs3mp-afk/monik.git`, получи main, сравни manifest/patch с распакованным кодом. Не копируй родительскую папку передачи, PRIVATE_REFERENCE или REFERENCE_HISTORY в checkout. Не пользуйся force-push или reset --hard. Защити локальные изменения, особенно если origin/main изменился во время работы.

## 2. Закрыть код и проверить пакет

В отдельном окружении:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements-test.txt
.venv/bin/python -m unittest discover -s tests -p 'test_*.py' -v
.venv/bin/python tests/fixture_validator.py tests
.venv/bin/python tests/wire_acceptance.py --output /tmp/monik-wire.json
.venv/bin/python tests/graph_browser_acceptance.py --output /tmp/monik-graph
```

Перед этими командами проверь, что Python совместим с закреплёнными версиями. Не меняй lock вслепую, не отключай проверки SSL для pip. Для обычной работы тестовые зависимости не нужны.

Сначала реализуй CLI-регистрацию из SOL_HANDOFF. Затем собери wheel и установи в чистый тестовый venv; вызови monik из другого каталога, чтобы исключить импорт исходников по cwd. Проверь русский help, TUI --once, интерактивный TUI через PTY, существующие команды и package-data web/labels/chart. Обновляй версию только после согласования фактической готовности, не как замену тестам.

## 3. Резервная копия перед заменой

Остановить **только обнаруженную службу monik**, а не Codex. User-вариант: `systemctl --user stop monik.service`; системный LAN: `sudo systemctl stop monik.service`. Перед изменением кода/схемы сделай backup прежним установленным CLI в новый приватный файл. Если старый CLI недоступен, используй штатный SQLite backup API для собственной БД, не копируй активные WAL-файлы наугад. Проверь quick_check копии.

Сохрани прежний commit, requirements, config и описание unit для rollback. Никогда не подменяй БД monik исходной базой Codex. Не публикуй backup/config/token. Не удаляй старый WAL/SHM пока их состояние не сохранено и monik не остановлен.

## 4. Собственные настройки и запуск

Прочитай `scripts/install.sh` и `enable-lan.py`: они пришли из ранней реализации. Уточни запрет дублирования активных служб и безопасную замену launcher/config, затем используй `--no-start` для контролируемой установки. `monik init` должен создавать только собственную конфигурацию и токен, не менять настройки Codex.

Ожидаемые собственные пути: `~/.config/monik/config.json`, `~/.config/monik/owner-token.txt`, `~/.local/share/monik/observatory.sqlite`. Config/token 0600, data directory 0700. Проверь default source paths, designated roots и shared-store сопоставление. При необходимости назначь `root_id` явно только в monik; это не resume/create команды Codex.

Запусти `monik doctor` и проверь Landlock ABI ≥ 3. Если защита не поддерживается или запрещена окружением, выясни причину и честно остановись на этом блокере, **не обходи её прямым `uvicorn create_app` или запуском от root**. Тестовая фабрика app разрешена только для искусственных источников.

Первый рабочий запуск: loopback `127.0.0.1:8666`. Убедись, что `monik serve` действительно работает от нужного пользователя, источники видны в «Качество», отсутствующие источники не стали нулями, web и TUI пользуются одним Collector. Проверь график `/token-graph` с реальными response_id. Не трать токены на дополнительные задания агентам только ради теста.

## 5. Постоянная служба и GitHub

После исправлений и тестов сделай нормальный commit/push в main. Выполни `git fetch origin`, проверь совпадение HEAD и origin/main и чистоту рабочего дерева. Разворачивай этот состав из постоянного пути. В приложении должен остаться только один user или system unit.

Для user-unit автозапуск при входе: `systemctl --user enable --now monik.service`. Если необходим запуск до входа пользователя, обсуди/зафиксируй `loginctl enable-linger` как отдельное изменение либо используй системный unit с `User=` владельца. Не включай два варианта одновременно. После перезапуска проверь журнал и HTTP, а не только сообщение команды enable.

## 6. LAN/TLS и телефон

Желательный порт владельца: 666. Адрес из прошлого обследования не гарантированно назначен; используй только фактический адрес интерфейса, достижимый с клиента. Не меняй IP/маршруты VM ради совпадения с примером.

Для LAN обязателен TLS. Штатный `scripts/enable-lan.py IP PORT` создаёт локальный CA и сертификат с IP SAN, устанавливает system unit от обычного пользователя и для низкого порта назначает только службе CAP_NET_BIND_SERVICE. Сначала проверь скрипт/пути/занятость порта и backup конфигурации. Запрещены setcap на системный Python, глобальное снижение порога привилегированных портов и root-приложение.

Передавать устройству можно только публичный `monik-ca.crt`; private `.key` остаётся на сервере. Сверь fingerprint доверенным способом. Не превращай игнорирование TLS-warning в нормальный способ входа. Firewall разрешает лишь нужный клиент/подсеть. При неясной связности допустим первоначальный собственный SSH-туннель к loopback; это нужно явно сообщить, а не назвать готовым LAN.

Проверь физический телефон: логин, 24/12/6/3/2/1, обе темы, сон/возврат, потеря Wi-Fi, SSE, смена ориентации, подсказки точки, выход и отсутствие старых приватных данных после него. Реальный Android не был проверен этой сборкой.

## 7. Rollback и завершение

Для отката останови только monik, верни прежний код/venv/config/unit и согласованную копию собственной БД. Не смешивай WAL/SHM от разных копий и не мигрируй БД Codex. Проверка восстановления предпочтительно сначала на отдельном демо-каталоге.

Финальное сообщение владельцу: commit, фактический URL, получение токена (`monik token`, не сам секрет), запуск `monik tui`, где график, 5–7 основных клавиш, две команды журнала/перезапуска и backup. Сообщи, что пауза/выход UI не останавливают агентов. Не расписывай новый огромный аудит в чат вместо краткой памятки; отчёт тестов и оставшиеся ограничения положи в репозиторий.
