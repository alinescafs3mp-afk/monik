# TUI: фильтр профиля исправлен

Первоначальный дефект был воспроизведён на `4fc1f8a28a2aaffcc2e99f35b398ee6e6b74b6a9`: при выборе Sol оба пути терминального обзора продолжали отображать Astra. Ошибка касалась карточек, не сохранённых token-измерений.

## Опубликованное исправление

`monik/tui.py` теперь применяет один фильтр карточек в разовом и фоновом чтении. Фильтр не меняет исходный ответ сервера, сохраняет остальные поля и не переинтерпретирует другие разделы как overview. Пауза, выбор события, справка и исторический режим из предыдущих коммитов сохранены.

Проверенный blob TUI: `f478afd6e74b4114c30e2234dff09665b3e15697`. Проверенный состав кода и тестов: `0f3bc55f1def2ee82bd94179fb57c889c622d3a8`.

## Диагностический контракт не изменён

`diagnostics/check_tui_profile.py` сохранён с прежним SHA `df7a3c1f23db6aa9cc087ec624d83814105af10b`. Теперь он завершается кодом 0 и возвращает:

```json
{
  "ok": true,
  "checks": {
    "once_excludes_other_profiles": true,
    "background_excludes_other_profiles": true,
    "client_thread_stopped": true
  }
}
```

Сценарий использует искусственный ответ и подменённый сетевой клиент. Добавлены четыре регрессии `tests/test_tui_profile.py`; одна вызывает исходную диагностику без изменения её условий.

```bash
python diagnostics/check_tui_profile.py
python -m unittest discover -s tests -p 'test_tui_profile.py' -v
```

## Граница интеграции

Штатная команда `monik tui` всё ещё не зарегистрирована: операция изменения CLI была отклонена инструментом. Исправление фильтра не заменяет регистрацию команды и не является альтернативным способом её запуска. Полный актуальный статус, результаты 73 тестов и оставшиеся замечания находятся в `INTEGRATION_AUDIT_20260910.md`.
