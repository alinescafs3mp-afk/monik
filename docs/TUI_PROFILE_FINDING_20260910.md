# Фильтр профиля: терминальный клиент и серверный обзор

Первоначальный дефект был воспроизведён на `4fc1f8a28a2aaffcc2e99f35b398ee6e6b74b6a9`: при выборе Sol оба пути терминального обзора продолжали отображать Astra. Ошибка касалась карточек, не сохранённых token-измерений.

## Предыдущее исправление клиента

`monik/tui.py` применяет один фильтр карточек в разовом и фоновом чтении. Фильтр не меняет исходный ответ сервера, сохраняет остальные поля и не переинтерпретирует другие разделы как overview. Пауза, выбор события, справка и исторический режим из предыдущих коммитов сохранены.

Исторически проверенный blob этого исправления TUI: `f478afd6e74b4114c30e2234dff09665b3e15697`. Состав той проверки: `0f3bc55f1def2ee82bd94179fb57c889c622d3a8`. Это не обозначение текущей вершины main.

`diagnostics/check_tui_profile.py` сохранён с прежним SHA `df7a3c1f23db6aa9cc087ec624d83814105af10b`. В предыдущем прогоне он завершался кодом 0 и возвращал:

```bash

python -m unittest discover -s tests -p 'test_tui_profile.py' -v
```

## Серверный обзор: дополнение от 10 сентября 2026

База серверной правки: `1aa65b3544983d7f176005fcb46a9ab08992c91e`. Итоговое изменение Python: `50f5fdb74d149477db5eddc60952bd4808d78b9f`. Новые проверки: `d6cdb88ff0513f987c047a9e19347f00c3fdf055`.

До этой правки `GET /api/v1/overview?profile=sol` вычислял и возвращал обе карточки, несмотря на фильтр. Клиентское исправление скрывало лишнюю карточку, но не убирало работу сервера и не исправляло ответ API.

Теперь `Queries.overview()` пропускает невыбранные профили до чтения настроек, целей и token-агрегатов. Для двух настроенных профилей с корневыми сессиями выбор одного вызывает две выборки usage вместо четырёх. Это проверенное сокращение числа запросов, не обещание двукратного ускорения или экономии модельных токенов: монитор модели не вызывает.

Отсутствующий либо пустой фильтр сохраняет все карточки и порядок конфигурации. Неизвестное имя даёт пустой список, а не все профили. Сопоставление точное, поддерживаются произвольные имена из конфигурации. Общий durable cursor остаётся глобальным: фильтрация карточек не меняет последовательность уведомлений SSE. Исторические границы, содержимое выбранной карточки, исходные параметры и записи БД сохраняются.

Конечный diff Python относительно базы состоит только из трёх строк фильтра в overview. При сверке исправлена случайная потеря строки сброса cumulative в промежуточном коммите; в итоговом файле прежняя логика cumulative полностью сохранена. Blob итогового `queries.py`: `bac5f87dd85f3c64b73472192127d3c66b28c75f`; совпадение с проверенным локальным файлом подтверждено чтением GitHub.

## Проверки серверного дополнения

Среда: Python 3.13.5, SQLite 3.46.1. Выполнявшиеся серверные модули восстановлены из доступных архивов и прочитанного GitHub-кода, затем сверены с Git blob SHA. Сетевой clone из контейнера недоступен.

| Набор | Результат |
|---|---|
| Новые `tests/test_overview_profile.py` | 13 PASS |
| Текущий опубликованный `tests/test_core.py` | 37 PASS, 1 SKIP |
| Итого unittest этого прогона | 51 тест: 50 PASS, 1 SKIP, без expectedFailure |
| Контрольные фикстуры | 11 PASS |
| Настоящий loopback HTTP/SSE | 23 PASS |

Новые проверки воспроизводят дефект на прежнем файле, затем проходят с теми же ожиданиями. Проверяются обе карточки отдельно, произвольный/неизвестный профиль, отсутствие лишних вычислений, глобальный cursor, исторические режимы, отсутствие изменений параметров и БД. API-контракт проверяется настоящим ASGI-приложением через TestClient, включая обязательную аутентификацию. Сетевой HTTP/SSE проверяется отдельно.

Это целевой серверный прогон, не повтор всего накопленного TUI-набора. Браузер, PTY, Android и systemd/HTTPS здесь заново не проверялись. Native Landlock пропущен из-за недоступного ABI; проверка отказа запуска без защиты входит в test_core.

```bash
python -m unittest discover -s tests -p 'test_overview_profile.py' -v
python -m unittest discover -s tests -p 'test_core.py' -v
python tests/fixture_validator.py tests
python tests/wire_acceptance.py --output /tmp/monik-wire.json
```

## Граница интеграции и обновление

Штатная команда `monik tui` всё ещё не зарегистрирована: новая попытка изменения CLI отклонена инструментом. Исправление ложного конфликта равных JSON int/float в снимках лимитов также не прошло запись. Оба кандидата исключены из опубликованного состава и приведённых результатов. CLI, storage.py, нормализатор, TUI и веб-файлы этим серверным дополнением не менялись. Версия пакета остаётся 0.1.0; новая production-приёмка не объявляется.

В существующем клоне выполнить `git pull --ff-only` и перезапустить только используемую службу monik: `systemctl --user restart monik.service` для пользовательской установки или `sudo systemctl restart monik.service` для системной LAN-службы. Не запускать оба варианта одновременно. Новые зависимости и миграция БД не нужны. Процессы и настройки Codex не меняются.
