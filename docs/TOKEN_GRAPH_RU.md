# График токенов: реализованный старт

## Доступ

В основной навигации есть «График токенов», отдельная страница `/token-graph` того же сервера. Используется существующая cookie владельца; без входа API возвращает 401 и страница предлагает перейти к обычному входу. Отдельного коллектора, базы или аккаунта нет.

Периоды: **24 / 12 / 6 / 3 / 2 / 1 час**, по умолчанию 6. Для Astra и Sol отдельные линии на общей оси, карточки сумм, средний темп за период и пик корзины. Можно выбрать input, output, cached input, uncached input, reasoning output или total. Легенда скрывает ряд только на графике/в таблице. Наведение и доступный с клавиатуры ползунок показывают детали; ниже есть числовая таблица.

Над графиком расположен текущий индекс аномалии **0–100**: зелёный 0–34, жёлтый 35–69, красный 70–100. Он сравнивает подтверждённый `total_tokens` за последние 15 минут с медианой измеренных 15-минутных корзин предыдущих 6 часов. Общий цвет берёт самый сильный сигнал среди совокупного темпа и отдельных профилей, чтобы всплеск одного профиля не растворялся в сумме. Уровень уверенности зависит от количества измеренных базовых корзин и недавних ответов.

Та же оценка вычисляется для каждой точки выбранных 1/2/3/6/12/24 часов и рисуется красной линией по отдельной правой шкале 0–100. Линию можно скрыть в легенде; ползунок показывает значение и профиль, который задал сигнал в выбранной точке. Каждая историческая точка использует только предшествующие ей 15 минут и шестичасовую базу, а не масштаб токеновой оси.

Под значениями Astra/Sol в блоке общей динамики показан live-прогноз: сколько процентов основного `codex/primary` лимита профиль израсходует за час при недавнем темпе. Накопленный процент здесь не показывается. Базовая оценка — изменение одного provider-счётчика примерно за 30 минут, приведённое к `%/ч`. Поскольку фактический счётчик обычно целочисленный, при нулевом полчасовом изменении окно расширяется до 60, затем 120 минут. Возраст и фактическая длина базы доступны рядом или в подсказке.

История прогноза образует отдельную чёрную линию с собственной автоматически подобранной шкалой `%/ч`; красный индекс продолжает жить на фиксированной шкале 0–100. Для общей чёрной линии выбирается максимальный доступный темп среди профилей в корзине: независимые профили не складываются и не усредняются. Нет сопоставимой пары снимков, сменилось окно/reset или счётчик уменьшился — остаётся разрыв, а не ноль. Расчёт никогда не выводит процент из количества токенов: провайдер не сообщает абсолютный знаменатель квоты.

Красная динамика остаётся локальной относительной диагностикой и не смешивается с чёрным provider-rate рядом. Ни одна из линий не оценивает деньги и не обещает полноту биллинга. Если подходящих измерений нет, индекс или темп лимита неизвестен, а не равен нулю. Подтверждённый неизменный provider-счётчик на всём доступном адаптивном окне даёт наблюдаемый темп 0; четырёхкратный токеновый всплеск при полной базе даёт красный индекс 100.

SSE сообщает о новых сохранённых событиях, после чего клиент обновляет агрегаты с ограничением частоты. Раз в 20 секунд сдвигается живое окно даже без событий. Пауза относится только к экрану. Скрытая вкладка закрывает SSE, возвращение догоняет данные. При потере доступа очищаются DOM и сохранённые данные клиента; resize или смена метрики их не возвращают.

## Метрики без ложной точности

Источник чисел: собственные `events` и `response_usage` монитора. Одна каноническая запись ответа учитывается один раз. `total=input+output`; cached является частью input, reasoning частью output. Показатель расходов не переводится в деньги или проценты подписки.

Ось X использует **event_at исходной записи ответа**, не время создания графика. Это ряд сохранённых измерений, не непрерывная телеметрия внутренней генерации модели. Нет source timestamp: ответ исключается с оси и отдельно считается по времени поступления в выбранный период.

Окно полуоткрытое: `[start,end)`. Корзины выровнены по UTC epoch. Шаги: 1 ч → 1 мин, 2 ч → 2 мин, 3 ч → 3 мин, 6 ч → 5 мин, 12 ч → 10 мин, 24 ч → 15 мин. Выдаётся не больше 98 точек на профиль. Крайние корзины могут быть неполными.

На оси Y: `значение корзины * 60 / полный шаг в секундах`. Неполная корзина не экстраполируется. Среднее за период: измеренная сумма / число минут окна. Это не гарантированная истинная скорость во время всей работы, поскольку охват всегда частичный.

Пустая корзина содержит null и разрыв линии, не доказанный нулевой расход. Реальный измеренный ноль остаётся нулём. Некорректные и спорные ответы исключены, их количество видно отдельно. Optional-метрики имеют собственные счётчики измерений. Соединение точек служит визуальной ориентацией, не доказательством потребления между ответами.

## API и время знания

`GET /api/v1/usage-series?hours=6` поддерживает только `hours`, необязательный `profile` и `at` в ISO 8601 с часовым поясом. Неизвестные/повторяющиеся параметры, произвольный диапазон, будущий at и неизвестный профиль отклоняются. Новый API требует ту же аутентификацию, что существующие private API; static HTML не содержит данных владельца.

`at` задаёт и конец окна, и горизонт знания. Включаются только записи, принятые до него; поздний backfill и поздние конфликты не подмешиваются. **Это намеренно не равнозначно реконструированному event-view старой ленты**, которая может использовать позднее найденные свидетельства. В живом режиме горизонт равен серверному now. UI выбора исторического at пока нет: это задача следующей доводки.

Курсор, агрегаты, счётчик записей без времени, ограниченный набор исходных ответов для линии аномалии и основной лимит читаются в одной транзакции Store. Пять SQL-запросов на снимок, без запроса на каждую корзину. Limit query материализует один валидный снимок на минуту в ограниченном диапазоне графика плюс не более двух часов базы; текущий снимок ищется максимум за семь дней. Поэтому live-оценка не зависит от выбранного размера корзины 1/2/3/6/12/24 ч. Сервер строит исторические оценки в памяти. Индекс спорных ответов используется явно. Размер ответа ограничен; максимальный профильный список 16. Схема БД и зависимости не изменены.

## Файлы

- `monik/series.py`: чистая read-проекция над собственной БД.
- `monik/chart_api.py`: фиксированные GET-маршруты; подключение в конце `create_app()`.
- `monik/web/token-graph.html`, `.css`, `.js`: отдельная страница, без CDN/сторонних JS-библиотек.
- `tests/test_token_series.py`: тесты вычислений, границ, неизвестных значений, текущего и исторического индекса аномалии, live `%/ч`, адаптивного окна, reset-контролей и API.
- `tests/graph_browser_acceptance.py`: настоящий loopback HTTP отдельно от обозначенного DOM-моста. Политику браузера не изменяет.

Текущие результаты перечислены в `ACCEPTANCE.md`. После обновления Python нужен рестарт только monik.
