# Приёмка v0.1.6

## Проверенный состав

Релиз сохраняет read-only архитектуру: нет Codex RPC, model calls, команд управления сессиями или записи в источники. Config и собственная SQLite schema остаются v1. Production `serve` запускается обычным пользователем и требует Linux Landlock ABI не ниже 3.

В v0.1.6 к закрытому производственному аудиту добавлены запрошенные владельцем изменения:

- под индексами общей динамики Astra/Sol показан live-прогноз `% лимита/ч`, без накопленного процента; фактическая база и устаревший снимок обозначены явно;
- прогноз выводится только из изменения сопоставимых `codex/primary` снимков примерно за 30 минут; при целочисленном плато база расширяется до 60/120 минут, а токены в provider-percent не конвертируются;
- отдельная чёрная линия с собственной автоматической шкалой `%/ч` показывает максимальный доступный профильный темп в корзине; темпы не складываются, неизвестное не становится нулём и не протягивается вперёд;

- экран лимитов выбирает только последнее основное наблюдение `codex/primary` для Astra и Sol; модельные квоты не удаляются из evidence, но не показываются рядом с основным лимитом;
- при явно настроенном `logs_db` свежий основной процент берётся из четырёх allowlisted `x-codex-*` полей локально сохранённых заголовков уже завершённого запроса; полный `feedback_log_body`, cookie, URL и request ID не возвращаются адаптеру и не сохраняются monik;
- строка сопоставляется с профилем только по доказанному root/parent-графу `thread_id`; неизвестная или спорная ветка пропускается;
- тихий профиль не исчезает, даже если 2000 последних исторических снимков принадлежат другому профилю; knowledge-time по-прежнему ограничивает выбор своим горизонтом;
- устаревшее основное значение подписано как последнее известное; monik не опрашивает provider и не вызывает `/status`, а использует локальное свидетельство от обычного запроса Codex;
- кнопка «Обновить сейчас» принудительно перечитывает локальный API без browser cache, показывает состояние выполнения и работает даже при остановленном автообновлении экрана;
- основное приложение после обновления возвращается на последнюю вкладку; в `localStorage` сохраняется только имя из whitelist, без токена и данных владельца;
- график показывает текущий индекс аномалии 0–100, confidence, значения Astra/Sol и красную историческую линию той же оценки для 1/2/3/6/12/24 часов;
- проверка conflict использует индекс canonical UID и не замедляет live-график полным перебором conflict-событий;
- новые `CommandExecution` не дублируют bulk output, а `monik compact` уплотняет старую собственную БД пакетно, без удаления событий/provenance;
- HTTPS LAN на высоком порту работает через owner user-service без sudo; низкий порт сохраняет узкую service capability;
- установщик сохраняет TLS LAN-конфигурацию при обновлении и проверяет уже поднятый сервис штатным клиентом.

Подробный разбор: `PRODUCTION_AUDIT_20260910.md`.

График дополнительно проверяет шесть периодов, метрики, null-разрывы, реальные нули, half-open границы, partial buckets, конфликт/late backfill, паузу, инспектор, таблицу, текущий индекс 0–100, красную историческую динамику, чёрную live `%/ч` линию, отдельную автошкалу, четыре элемента легенды, профильные прогнозы без накопленного процента и очистку данных после 401.

На действующей собственной БД размером около 1,8 ГБ шесть последовательных read-only запросов графика для 1/2/3/6/12/24 часов заняли 0,62–0,69 секунды каждый, включая красную динамику и новую чёрную `%/ч` линию. Во всех шести ответах текущие профильные прогнозы совпали. Limit query остаётся одним запросом на снимок: минутные опорные точки ограничены выбранным окном плюс двумя часами, а поиск текущего события использует профильный индекс и семидневную границу. Это локальные измерения, не SLA.

На целевой машине подтверждены единственная owner user-служба, точный private-IP bind на непривилегированном порту, IP SAN, проверка локальным CA, авторизованные limits/usage-series, TUI и сохранение HTTPS-конфигурации после повторного запуска установщика. Firewall самой VM отключён; достижимость с физического клиента зависит также от режима сети VM.

## Границы результата

Физический телефон, его trust store, реальная смена Wi-Fi и внешний firewall требуют отдельного клиентского устройства и не доказываются процессом внутри VM. Monik показывает частичную локальную историю: скрытые рассуждения, streaming-дельты, provider billing, удалённые до чтения байты и источники вне явной конфигурации недоступны. Значение лимита меняется только после локально сохранённого ответа Codex и может кратко отставать от интерактивного `/status` до следующего цикла коллектора.
