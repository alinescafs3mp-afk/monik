Числа в разных наборах нельзя складывать в число независимых требований: некоторые сценарии пересекаются. В UI-тесте `EventSource` заменён явно обозначенным адаптером уведомлений. Проверка настоящего SSE выполнена отдельно Python-клиентом, не через этот адаптер. Разрешённый браузерный E2E-сценарий подготовлен в `tests/browser_acceptance.py`, но здесь не был пройден.

### Измерение задержки

Восемь добавлений в синтетический JSONL при уже существующей истории из 3000 событий, период коллектора 0,2 секунды: от завершения записи до получения SSE Python-клиентом наблюдалось 0,237–0,281 секунды в исходном прогоне. Это небольшой локальный образец, не SLA, не замер физического телефона, не гарантия для многогигабайтной базы. Полный массив находится в `evidence/wire.json`; повторный прогон даёт собственные значения.

### Проверенные инварианты

Импорт переживает незавершённую строку, перезапуск коллектора, смену inode, усечение, повреждённую строку, неизвестный тип и превышение лимита размера. Ошибка записи в собственную SQLite не продвигает курсор источника. Две доставки одного ответа не удваивают расход. Конфликтующие записи сохраняют первоначальную каноническую метрику и отдельное свидетельство конфликта. Накопительные счётчики, расход ответов, контекст и лимиты не смешиваются.

Проверены общий физический каталог, разные деревья Astra/Sol, отказ при неоднозначной идентичности, появление нового root, продолжение Sol при исчезновении источника Astra. LIVE не ждёт глубокого импорта истории. Для снимков действует время наблюдения; более поздние настройки не применяются задним числом. Поиск работает с русским текстом и строками кода. Обновление метаданных не делает старый статус свежим.

Проверены API-аутентификация, cookie, Origin, ограничение ошибок входа, запрет произвольных путей и управляющих методов, запрет plaintext LAN и пересечения собственной базы с деревьями источников. Большие значения ограничены до сохранения, типовые секреты редактируются, скрытый reasoning не сохраняется. Это не доказательство полноты маскирования произвольных секретов.

Офлайн-браузер проверяет ширины 360, 390, 412, 768 и 1440 px, основные цели нажатия от 44 px, обе темы, все вкладки, поиск, сравнение A/B, подробности, текстовую обработку потенциального HTML, отсутствие скачка прокрутки и удержание исторического момента T.

## Воспроизведение

Из корня клонированного репозитория, обычным пользователем:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.lock -r requirements-test.txt
.venv/bin/python -m unittest discover -s tests -p 'test_*.py' -v
.venv/bin/python tests/fixture_validator.py tests
.venv/bin/python tests/wire_acceptance.py --output test-results/wire.json
.venv/bin/python -m compileall -q monik tests scripts
bash -n scripts/install.sh scripts/uninstall.sh
# Необязательная проверка синтаксиса JS, если установлен Node.js:
node --check monik/web/app.js
# Chromium должен быть доступен как /usr/bin/chromium.
.venv/bin/python tests/offline_browser.py --output test-results/offline-ui
# Только в среде, где браузеру разрешены локальные сетевые соединения:
.venv/bin/python tests/browser_acceptance.py --output test-results/native-browser
```

Все тесты используют временные синтетические или обезличенные источники. Они не запускают модели и не меняют конфигурацию Codex. Импорт библиотечного ASGI-приложения в тесте не является production-запуском: обязательная Landlock-изоляция устанавливается CLI перед запуском потоков.

## Целевая приёмка после установки

### 1. Изоляция и определение источников

Запустить `monik doctor`, проверить ABI Landlock ≥ 3, собственную папку данных, существование реестров/баз и правильные root. Убедиться, что неизвестные или отсутствующие источники видны в «Качество», а не изображаются нулевым расходом. В `systemctl --user status monik.service` сервис должен быть активен; ошибки Landlock нельзя обходить отключением защиты.

Повторить полный `test_core.py`: на поддерживаемом ядре тест нативной Landlock-границы должен стать PASS, а не SKIP. Он работает с временными файлами и проверяет отказ записи вне разрешённой папки. Отдельно проверить рабочие WAL-базы: разрешённое чтение или явно показанный отказ безопаснее скрытого ослабления границы ради успешного чтения.

### 2. O13: настоящие независимые TUI

На обычной рабочей задаче владельца сравнить запуски с монитором и без него. Не отправлять специальные команды моделям только ради монитора. Зафиксировать процессы TUI, их фактические model/effort/tier и доступные безопасные диагностические показатели. Включить, открыть в двух браузерах и остановить **только** monik. TUI должны продолжать работу без новых управляющих RPC, переподключений со стороны monik, смены настроек и вызовов моделей. Файлы Codex могут изменяться самими TUI: один лишь diff активного файла не доказывает запись монитора. Для строгого доказательства нужны доступные владельцу средства атрибуции системных вызовов по PID.

Не замораживать TUI, не выполнять `kill`, не закрывать дочерние задачи и не менять source permissions ради этой проверки. Нормальные паузы, завершения и возобновления владельца служат наблюдаемыми сценариями, а не командами тестового монитора.

### 3. Функциональность и история

Проверить принадлежность корней и дочерних веток обоим профилям, сообщения и tool calls, смену модели/effort/tier, цели, известные статусы и их возраст. Сверить несколько `response_id` с источником, исходные окна лимитов и provenance. Выбрать время T до изменения настроек, убедиться в отсутствии будущих значений; сравнить «По времени события» и «Что было известно». Перезапустить **только monik**: дубликатов расхода быть не должно, собственная история должна сохраниться.

На копиях источников можно воспроизвести ротацию, обрыв строки, отсутствие одной стороны и большие ответы. Никогда не повреждать настоящий rollout для acceptance. Замерить потребление CPU/RAM и задержку LIVE при масштабе владельца, отдельно указав длину прогона, нагрузку и размер истории.

### 4. LAN, HTTPS и Android

Использовать реально назначенный адрес машины. После `scripts/enable-lan.py` установить публичный CA-сертификат в доверенное хранилище нужного устройства через доверенный канал; проверить SHA-256 отпечаток. Не переносить CA private key. Разрешить сетевой доступ только нужным устройствам. Проверить логин, Secure/HttpOnly cookie, обновление без перезагрузки, сон/возврат вкладки, смену Wi-Fi, выход, обе темы и отсутствие горизонтального скролла. На реальном телефоне отдельно измерить завершение записи → появление события на экране.

### 5. Восстановление

Создать резервную копию собственной SQLite через `monik backup`, выполнить `quick_check` копии. Для практической проверки восстановления использовать отдельную папку/демо, не заменять активную базу без остановки monik. Остановка или удаление монитора не должны требовать ремонта источников Codex.

## Честные ограничения релиза

История доступна только там, где есть читаемые файлы и сохранённые события; общий охват всегда `partial`. Thread-history SQLite backfill, тела файлов handoff, скрытые рассуждения, временные streaming deltas и достоверный учёт биллинга отсутствуют. Дерево/назначения до первого наблюдения могут быть неизвестны. Нет автоматического удаления старой истории и обещанного объёма хранилища без замера на целевых данных. Ни эти ограничения, ни непроведённые испытания не маскируются зелёной отметкой «полная приёмка».
