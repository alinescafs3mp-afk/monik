# Полная передача monik CLI-Солу

> Историческая инструкция передачи. Для текущего состояния используй `ACCEPTANCE.md`, `TOKEN_GRAPH_RU.md` и `RELEASE_BACKLOG_RU.md`.

## Задание владельца

Дест передаёт тебе проект отдельно от работы с Астрой. Цель: закончить надёжный монитор, довести веб и TUI, опубликовать результат в `alinescafs3mp-afk/monik` → `main`, **полностью развернуть его в системе** и написать владельцу короткую инструкцию. Не ограничивайся аудитом, новым архивом или советами без выполнения доступной установки.

Владелец разрешил завершение, push и развёртывание monik. Это не разрешение менять Пятницу, настройки Codex, effort ultra, модели, параллелизм, hooks, Goals, native PEER, Sol-link или управлять чужими процессами. При реально неизвестной сетевой конфигурации сначала используй безопасный loopback и сохрани рабочее состояние машины.

## Единственная исходная точка

В архиве рабочий проект только в папке `monik/`. Он построен на опубликованном main `40b5424143a5d2d80717089c52085fce3d5bf4fd`; все 73 файла этой базы восстановлены и сверены с Git blob SHA, общий tree равен `d7224a032897d10ce62a4f9ed1aa7d4d2ac60442`. Сетевого clone в сборочном контейнере не было. Информация о фактическом последнем опубликованном коммите и совпадении с архивом находится во внешнем `VERIFICATION/publication.json`.

Новый состав добавляет отдельную страницу графика, read API, вычисления, тесты, ссылки навигации и эти инструкции. Пакет остаётся `monik`, версия пока 0.1.0, конфиг и собственная SQLite schema v1. Не переносить поверх него параллельные экспериментальные `observatory`/0.2 из старых архивов. Они сохранены исключительно для справки. Старые числа 58/82/132 теста относятся к другим составам; актуальна только текущая проверка.

В архив не включены .git, venv, действующая БД или секреты. Полная Git-история остаётся на GitHub. Первичное приватное обследование помещено вне репозитория в `PRIVATE_REFERENCE/DO_NOT_UPLOAD/`. Открой его START_HERE/IMPLEMENTATION_HANDOFF/UI_AND_ACCEPTANCE при необходимости контекста; не запускай старые probe-скрипты автоматически и не публикуй архив.

## Что уже работает

Сбор разрешённых rollout/lifecycle/registry/Sol-link, доказанное сопоставление корней и детей при shared storage, собственная SQLite с историей/provenance/FTS, dedupe ответов, отдельные снимки лимитов, read-only HTTP/SSE, русский веб и модуль curses TUI. Сохранены исправления временных границ detail, поздних конфликтов usage, согласованного overview, фильтра профиля, кэша отрисовки, прокрутки, справки и навигации TUI.

График описан полностью в `TOKEN_GRAPH_RU.md`: 24/12/6/3/2/1 ч, метрики, линии профилей, среднее/пики, данные точки, null-разрывы, таблица, LIVE и пауза. Это работающая начальная реализация, а не макет. Данные испытаний синтетические, не расход аккаунтов Деста.

## Порядок работы без повторной переписи

### 1. Зафиксировать состояние

Проверь текущий checkout, `git status`, origin, актуальный origin/main и собственные службы monik. Не выполняй `reset --hard`. Если работаешь из распакованной папки без .git, создай соседний чистый clone и сравни его с архивом, используй приложенный review.patch и manifest. Если main ушёл вперёд, согласуй различия, не затирай их. Размещай рабочий checkout отдельно от Friday и её venv.

Прочитай актуальные файлы и `RELEASE_BACKLOG_RU.md`. Повтори полный unittest, fixture-validator и wire-тест до новых правок. Разберись с реальными расхождениями вместо объявления старого протокола новой приёмкой.

### 2. Закрыть обязательные интеграционные замечания

**CLI TUI.** В `monik/cli.py` отсутствует штатная подкоманда. Модуль готов: `monik.tui.run(config, *, once=False, page='overview', profile=None, at=None, ca_file=None)`. Добавь обычную подкоманду argparse с `--config`, `--once`, `--page` (overview/activity/tokens/limits/tree/quality), `--profile`, `--at`, `--ca-file`; lazy import curses только для TUI. Используй существующий `load()`, не создавай Collector или второй сервер. Проверь help, неверные параметры, no-TTY/--once, установленный wheel вне исходного каталога, настоящий HTTP/PTY, resize, q/й и восстановление терминала. Не выводи токен в лог.

**Повторный импорт лимита.** Численно равный reset timestamp может отличаться JSON int/float и вызвать ложный conflict. Исправляй узко, с регрессией старой канонической записи и повторной доставки. Не переписывай всю БД/UID и не делай Python `True == 1` критерием эквивалентности. Настоящее изменение числа/окна/типа должно оставаться видимым. Старые false-positive конфликты разбирать отдельно, не удалять молча.

**Список профилей веба.** Сервер overview теперь правильно возвращает только выбранный профиль, но прежний JS вызывает `syncProfiles(o.profiles)`. Проверь и исправь сужение списка до одной карточки; каталог профилей должен сохраняться отдельно от отфильтрованного снимка. Регрессия: все → Sol → автообновление → Astra → все, затем выход/вход и неизвестное имя. Не отменять серверный фильтр ради UI.

**Эксплуатация.** Перед настоящими источниками проверь атомарность own-config записи, приватность token/lock-файлов, аккуратное согласование user/system unit, backup и корректный останов только monik. Старый installer не является гарантированно безопасным обновлятором активной службы: прочитай его перед запуском.

### 3. Довести график и проверить реальные сценарии

Сначала 19 новых unit/API тестов и весь накопленный набор; потом настоящий браузер с обычной сетью и действующими cookie/SSE. В этой среде Chromium запрещал локальную навигацию; DOM-мост явно тестовый, не приёмка транспорта. Проверь CSP, вход/выход, отсутствие восстановления private DOM после 401, быстрые переключения периода, возврат из сна, частичные окна, разрывы, реальные нули и согласованность графика с исходными response_id.

Проверь цену запросов на объёме владельца: каждый график агрегирует до 24 ч раз в 20 секунд плюс throttled committed events. Не загружай все тексты в браузер и не делай новый сборщик на вкладку. По необходимости добавь небольшой серверный cache с инвалидированием курсором/окном, но не теряй поздние конфликты и границы знания.

Опциональные красивые улучшения бери после обязательных задач. Важно закончить единый продукт, а не увеличить число половинчатых модулей.

### 4. Опубликовать и развернуть

Порядок в `DEPLOYMENT_FOR_SOL_RU.md`. Финальный push должен идти в main обычным Git, без force. Проверить совпадение локального HEAD и origin/main. Развернуть именно этот состав из постоянного checkout, не временной распаковки. Не поднимать user и system LAN службы одновременно.

Настрой локальный доступ сначала; затем согласованный LAN/TLS на реально назначенном адресе. Порт 666 относится к пожеланию владельца, не к доказанной доступности IP. Для низкого порта допустима только service-scoped CAP_NET_BIND_SERVICE, не root-приложение и не глобальное изменение sysctl/Python capabilities.

### 5. Закрыть передачу владельцу

Дай реальный commit, что установлено/где хранится, фактический URL, как получить токен без раскрытия его в чате, команду TUI, расположение графика, базовые клавиши, журнал, backup и останов/обновление только монитора. Памятка короткая; подробности в репозитории. Отдельно скажи, какие живые проверки ещё не удалось сделать. Не объявляй production готовым по синтетическому тесту.

## Нельзя потерять при рефакторинге

Стабильные ID и временные границы, несмешивание профилей/учёток, cached/reasoning subset-семантика, provenance и момент первого конфликта, нулевые timestamp, durable cursor, отдельные live/backfill позиции, частичные JSONL-строки, bounded output, read-only sources, no model calls, Landlock, UI/TUI инертность чужого текста. Русификация только оболочки. Для тестовых ротаций и disk-full использовать копии, не настоящие rollout.

Оригинальная матрица O1–O20 находится в приватном обследовании; в частности O11 (Android sleep/reconnect), O13 (невмешательство в настоящие TUI), O15 (очень большие outputs) не считать полностью закрытыми одним unit-тестом.
