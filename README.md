# monik · Codex Observatory

Локальная обсерватория для **двух независимых Codex TUI: Astra и Sol**. Русский интерфейс, live-лента, история, токены, снимки лимитов и дерево агентов. Монитор не запускает модели, не отправляет RPC в Codex и не управляет его процессами.

**Версия 0.1.2:** актуальные атомарные снимки лимитов, индекс аномалии расхода 0–100, HTTPS-доступ из LAN без root на высоком порту и уплотнение собственной истории. Подробный статус: [docs/ACCEPTANCE.md](docs/ACCEPTANCE.md).

## Что работает

Обзор Astra/Sol; сообщения, доступные reasoning summaries, вызовы и результаты инструментов; настройки с доказательствами; цели из rollout; lifecycle и метаданные Sol-link; поиск по русскому тексту, ID, коду и пути; срез на момент T и сравнение A/B; тёмная и светлая темы; адаптивный интерфейс. Отдельный `/token-graph` показывает 24/12/6/3/2/1 часа, метрики по профилям, детали корзин, таблицу, LIVE, паузу экрана и заметный индекс аномалии 0–100.

Токены считаются по уникальным `(profile, original_thread_id, response_id)`. Кэш уже входит во ввод, reasoning уже входит в вывод. Накопительные счётчики и проценты лимита не прибавляются к расходу. Неизвестное остаётся неизвестным. Идентичность профиля определяется root/parent-графом, а не именем модели или общим каталогом.

Источники читаются инкрементально. Новые записи, недавний хвост и глубокая история имеют независимые позиции чтения. Перезапуск сохраняет курсоры. Повторы с устойчивым ID не удваиваются; расхождения сохраняются отдельно. Незавершённая строка ждёт завершения. Замена inode, усечение, большие и неизвестные записи обрабатываются с явными диагностическими событиями.

## Установка на Ubuntu

Запускать **тем же обычным пользователем**, которому принадлежат TUI. Не запускать весь установщик через sudo.

```bash
sudo apt-get update
sudo apt-get install -y git python3 python3-venv openssl

git clone https://github.com/alinescafs3mp-afk/monik.git "$HOME/monik"
cd "$HOME/monik"
bash scripts/install.sh

"$HOME/.local/bin/monik" token
systemctl --user status monik.service --no-pager
```

Открыть **http://127.0.0.1:8666** на этой машине. Для входа используется токен из последней команды, не пароль Codex и не OpenAI API key. Токен не попадает в URL или localStorage. Сервер не пишет HTTP access log.

Терминальный интерфейс использует тот же сервер и не запускает второй Collector:

```bash
~/.local/bin/monik tui
~/.local/bin/monik tui --once --page tokens
```

Требуются Linux x86_64/aarch64, Python 3.11+, SQLite с FTS5 и **Landlock ABI не ниже 3**. На неподдерживаемом/запрещающем Landlock ядре `serve` отказывается запускаться. Небезопасного автоматического fallback нет. Диагностика: `~/.local/bin/monik doctor`. Установка без запуска: `bash scripts/install.sh --no-start`.

Установщик создаёт только собственные venv, launcher, конфигурацию и пользовательский systemd unit. Перед заменой собственной БД он делает проверенную резервную копию, а при ошибке возвращает прежний user-состав. Активная system-служба исключает параллельный user-запуск. Данные Codex, его профили, reasoning effort и количество субагентов не изменяются. Каталог установки в этой версии должен быть без пробелов, кавычек и `%`.

Пользовательская служба запускается при входе пользователя. Для запуска после перезагрузки без входа, с явного решения владельца:

```bash
sudo loginctl enable-linger "$USER"
```

### Браузер находится на другом компьютере

Для первоначальной проверки можно оставить сервер на loopback и открыть SSH-туннель с клиентского компьютера:

```bash
ssh -N -L 8666:127.0.0.1:8666 LOGIN@HOST
```

Затем открыть http://127.0.0.1:8666 на клиенте. `LOGIN@HOST` заменить на свою машину. Это не открывает веб-порт в LAN.

## Источники и root-сессии

Конфигурация хранится в `~/.config/monik/config.json`, токен в `~/.config/monik/owner-token.txt`, собственная история в `~/.local/share/monik/observatory.sqlite`.

По умолчанию:

| Профиль | Codex home | Root из registry |
|---|---|---|
| Astra | `~/.codex` | `~/.jericho/runtime/subagent-lifecycle/state/astra/registry.json` |
| Sol | `~/.config/codex-multi/profiles/solgoodman` | `~/.jericho/runtime/subagent-lifecycle/state/sol/registry.json` |

`state_5.sqlite` и `thread_spawn_edges` дают пути rollout и дочерние ветки. Реальные root ID и пути пользователя в репозитории не зашиты. Общие symlink-каталоги двух профилей не означают общую идентичность.

Если registry отсутствует, root можно явно задать в **конфигурации monik**:

```bash
~/.local/bin/monik roots --astra ASTRA_THREAD_UUID --sol SOL_THREAD_UUID
systemctl --user restart monik.service
```

Это не создаёт, не возобновляет и не останавливает сессии Codex. При автоматическом режиме смена designated root отслеживается; после ручного закрепления нужно снова изменить root вручную либо вернуть `root_id: null` в конфигурации monik. История ранее привязанных веток сохраняется.

`Pandora box`, `auth.json`, переменные окружения процессов и содержимое конфигурации Codex не читаются. Неизвестная структура state DB, отсутствующий WAL/SHM или конфликт владельцев не исправляются за счёт источника: адаптер показывает ошибку/unknown. Никаких `immutable=1` для живой базы и никаких app-server fallback.

## HTTPS в LAN

Это отдельный, явный шаг. Использовать **адрес, действительно назначенный этой машине и достижимый с клиента**. Скрипт проверяет адрес, но не назначает его, не меняет маршруты и не открывает firewall.

```bash
cd "$HOME/monik"
# Пример. Заменить адрес на фактический IP своей машины.
.venv/bin/python scripts/enable-lan.py 192.168.50.10 8443
```

Скрипт создаст локальный CA и сертификат с IP SAN. На порту 8443 остаётся обычная пользовательская служба, поэтому sudo не нужен. Если явно выбран порт ниже 1024, например 666, скрипт установит systemd-службу от имени обычного владельца и выдаст **только этой службе** `CAP_NET_BIND_SERVICE`; для этого шага потребуется sudo. Ни `setcap` на Python, ни изменения `net.ipv4.ip_unprivileged_port_start` не используются.

На клиент нужно доверенным способом перенести и установить **только** `~/.config/monik/tls/monik-ca.crt`. Приватные `*.key` никому не передавать и в Git не добавлять. Способ доверия локальному CA зависит от ОС/браузера и проверяется отдельно. Не обходить предупреждения TLS как постоянный способ работы. Серверный сертификат действует 365 дней; обновление требует остановки службы и повторного явного выпуска.

После настройки TLS и проверки сети разрешить вход только нужному клиенту. Пример узкого правила, с заменой обоих адресов:

```bash
sudo ufw allow from 192.168.50.20 to 192.168.50.10 port 8443 proto tcp
systemctl --user status monik.service --no-pager
```

Это пример для своей сети, не команда, которую нужно выполнять с чужими адресами. За NAT/внутренней сетью виртуалки может потребоваться отдельное решение по связности. Скрипт его не угадывает.

Если LAN-настройка прервалась, скрипт сам возвращает прежнюю конфигурацию и службу; исходный снимок также хранится в `~/.config/monik/config.before-lan.json`. Codex перезапускать не требуется.

## История, детали и ограничения

**Время события** показывает записи, относящиеся к моменту T, включая найденный позднее backfill. **Когда узнал монитор** дополнительно ограничивает время поступления. Снимки state/registry не задним числом доказывают старые статусы. Настройки показываются как последние известные значения; у каждого поля есть собственный provenance в API. Это не доказательство текущей активности процесса.

Лента ограничена 80 событиями на странице; API допускает до 200. Длинные payload открываются страницами по 32 768 символов. На входе действует предел строки 16 MiB и ограничение сохраняемого текста/структуры. Содержимое, срезанное при приёме, не восстанавливается из собственной базы. Большие и неизвестные записи не превращаются в измерения.

FTS ищет начала слов, отдельный режим ищет буквальную подстроку. Морфология русского языка не обещается. Stable link указывает на UID события и, при необходимости, момент T. Экспорт содержит только выбранную ограниченную страницу очищенных записей.

Не реализованы: чтение `thread_history_1.sqlite`, тела файлов handoff, сетевые ретраи, streaming-дельты, скрытые рассуждения, биллинг, независимый опрос account rate limits. Лимиты появляются только из сохранённых источником снимков и явно стареют. Текущими считаются все окна одного новейшего атомарного снимка профиля; старые provider limit ID остаются только в истории. Основные суммы охватывают все известные ветки профиля, включая предыдущие root-сессии; фильтр thread ограничивает конкретную ветку. Это не точная стоимость подписки.

Автоматическое удаление истории не включено. Следить за свободным местом во вкладке «Качество». Ротация и усечение видимы, но уже удалённые до чтения байты восстановить невозможно. При потере диска/источника монитор не чинит и не трогает Codex.

## Безопасность и границы проверки

Production-команда `serve` до запуска потоков применяет Landlock: создание/запись/удаление/перемещение/усечение файлов разрешаются только внутри собственного data directory. Это дополнительная файловая граница, не полная песочница чтения, сети и процессов. Служба работает не от root. LAN без TLS отклоняется. API не имеет команд запуска, resume, unsubscribe, изменения настроек или выполнения инструментов.

Очистка секретов выполняется до записи; opaque reasoning удаляется. **Автоматическая очистка best-effort**, поэтому собственная БД, резервные копии, токен и диагностические выгрузки остаются чувствительными. Их нельзя публиковать. См. [docs/SECURITY.md](docs/SECURITY.md).

## Обслуживание

```bash
# Пользовательский вариант
journalctl --user -u monik.service -f
systemctl --user restart monik.service

# Резервная копия собственной БД: имя должно быть новым
~/.local/bin/monik backup "$HOME/monik-backup-$(date +%Y%m%d-%H%M%S).sqlite"

# Убрать старые раздутые payload из собственной БД без удаления событий/provenance
systemctl --user stop monik.service
~/.local/bin/monik compact
systemctl --user start monik.service

# Только для явно выбранного низкого LAN-порта с system-службой — вместо --user
sudo journalctl -u monik.service -f
sudo systemctl restart monik.service
```

Перед восстановлением остановить **только monik**. Сохранить текущие `observatory.sqlite`, `-wal`, `-shm` отдельно, восстановить проверенный backup как `observatory.sqlite`, установить 0600, убрать старые sidecar-файлы monik из рабочего каталога и запустить службу. Никогда не переносить sidecar-файлы от другой версии БД. UI при слишком новом SSE cursor получает явный reset.

Обновление: остановить monik, сделать собственную резервную копию, выполнить `git pull --ff-only`, обновить venv по `requirements.lock`, запустить тесты и monik. Не выполнять git reset или автоматическую очистку дерева, где есть свои изменения. Удаление пользовательской службы: `bash scripts/uninstall.sh`; история и конфигурация намеренно сохраняются.

## Проверки

```bash
cd "$HOME/monik"
.venv/bin/python -m pip install -r requirements-test.txt
.venv/bin/python -m unittest discover -s tests -p 'test_*.py' -v
.venv/bin/python tests/fixture_validator.py tests
.venv/bin/python tests/wire_acceptance.py --output /tmp/monik-wire.json

# При наличии Chromium и разрешённой локальной навигации
.venv/bin/python tests/browser_acceptance.py --chromium /usr/bin/chromium --output /tmp/monik-browser
.venv/bin/python tests/graph_browser_acceptance.py --chromium /usr/bin/chromium --output /tmp/monik-graph
```

Релиз проверен в native Chromium через loopback: вход, фильтры профилей, настоящий EventSource, обновление графика по SSE, logout/relogin, потеря связи, 401, адаптивные ширины и отсутствие внешних запросов. Отдельно проверены wire HTTP/SSE, production Landlock, wheel и пользовательский unit. Физический Android и LAN/TLS с локальным CA требуют конкретной сети и клиентского устройства и в эту приёмку не входили.

Для изолированной демонстрации без чтения реальных профилей:

```bash
~/.local/bin/monik demo --directory "$HOME/monik-demo" --prepare-only
~/.local/bin/monik token --config "$HOME/monik-demo/config.json"
~/.local/bin/monik serve --config "$HOME/monik-demo/config.json"
```

Демо тоже использует production-команду с обязательным Landlock. Каталог должен быть новым или пустым; демонстрационные источники явно помечены в UI.
